# Design 真实提示词目录

## 为什么调整网页

用户认为平台功能和概念场景太抽象，想先知道库里到底收录了什么提示词。因此网页第一入口改为真实内容目录；原有平台能力、接入方式和教学演练保留在次要导航。

## 采集范围与证据

- 用户指定：[Design 分类页](https://prompts.chat/prompts?category=cmmnlanki0004l204gai1zuii)。
- 数据读取：[公开列表 API](https://prompts.chat/api/prompts?category=cmmnlanki0004l204gai1zuii&perPage=50)。
- 采集日期：2026-09-17。
- API 返回 `total=30`、`totalPages=1`、30 个不重复 ID；本次已覆盖该分类的全部返回记录，不是全站全集，也不包括其他分类或未来新增内容。
- 官网类型统计：24 TEXT、5 IMAGE、1 SKILL。类型保留原值，实际用途由阅读正文后解释。
- 逐条 ID、来源链接、原文 SHA-256 与接口响应哈希记录在 [catalog-snapshot.json](catalog-snapshot.json)。
- 中文编辑说明记录在 [catalog-editorial.json](catalog-editorial.json)，网页数据在 [catalog-data.js](../app/catalog-data.js)。所有原文均完整保留，未用中文概述替代原文。

只保留标题、正文、内容类型、来源链接及内容更新时间，未引入 API 返回的头像、作者账户资料等字段。网页不实时请求上游；分类数据是采集时的静态快照。

## 阅读后发现的具体边界

1. `Web Typography` 的类型是 IMAGE，但正文为前端排版规则，不能只按类型理解。
2. 若干 TEXT 条目的正文实际描述图像或视频生成需求。
3. 唯一标为 SKILL 的企业微信／钉钉测试页条目，Instructions 仍保留 `Step 1: ...` 和 `Step 2: ...`，属于未完成骨架，不应描述成可直接安装使用的成熟技能。
4. 有些条目只是简短想法，有些包含明确结构，还有一条设计交接模板超过两万字符。不同条目使用前需要补充、替换或裁剪，收录不等于质量认证。
5. “Apple-Level”等词为原作者标题，不是官方认证；关于图像质量、性能指标、专利绘图规范等要求，均不能据提示词文本认定效果或合规性已验证。

## 网页怎样呈现

- 目录：按网站与 UI、规范与交接、检查与上线、品牌海报、插画图像、游戏音视频、Skill 条目分组。
- 每条：中文用途、需要准备的材料、期望输出、具体例子、阅读提醒、官网类型、原标题与来源。
- 详情：完整原文、原文复制下载、附加本次任务后复制下载。用户填写的内容只在页面内存处理。
- 组合：用真实条目串联“从零做网站”“改造旧网站”“Logo 与活动海报”三条路径，共 13 个步骤。
- 组合顺序为本研究建议，不是官方一键自动化，也不是已经执行的模型实验。
