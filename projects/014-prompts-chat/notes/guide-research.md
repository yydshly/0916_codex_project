# 提示词有哪些方面，以及对我们的引导

研究日期：2026-09-17。本文基于官网公开目录快照、32 篇跨领域样本正文、之前的 30 篇 Design 详解，以及固定版本源码阅读。优先级是针对我们当前开源研究与网页制作任务的判断，不是效果排名。

## 结论

把 prompts.chat 当作按任务查阅的参考资料库比较合适。我们最值得提取的是任务拆解、检查清单、输出结构、领域注意事项和具体风格描述。遇到不熟悉或反复出现的工作时，它可能帮助补齐遗漏；简单改写、翻译或摘要，直接把目标说清楚通常就足以开始，不必先搜一段长提示词。

当前没有对照实验能证明本次样本普遍优于直接表达需求。内容多、标题专业或获得关注，都不能替代任务结果的验证。我们的策略是：按需查阅 → 提取有用要求 → 结合真实材料使用 → 对照检查 → 有帮助才沉淀。

## 目录来源和覆盖范围

- 来源：[公开目录](https://prompts.chat/prompts)及[公开 API 第一页](https://prompts.chat/api/prompts?perPage=100&sort=oldest&page=1)。本次读取 23 页，每页最多 100 条，按 `oldest` 排序。所有分页报告的总量均为 2,270，获取 2,270 条且 ID 无重复。
- 采集结束：2026-09-17 02:07:57 UTC（北京时间 10:07:57）。详细元数据及正文 SHA-256 见 [guide-snapshot.json](guide-snapshot.json)。这不是后续自动更新的实时镜像。
- 52 个有内容的官网分类包含 1,554 条；另有 716 条没有分类。未收录零条目分类，不声称拿到了官网全部分类定义。
- 按官网分类归并为 16 个使用方向，保证 52 个分类全部覆盖且不重复。**没有逐条重新判断 2,270 条的语义归属**；原标签可能错误，方向数量是目录归并数量，不是推荐数量。
- API 排除了私有、未列出、已删除内容，以及存在非 `related` 入边的流程中间条目。故“完整索引”仅指当次公开目录查询返回全集，不是站内整个数据库。对应[固定版本 API 源码](https://github.com/f/prompts.chat/blob/f78a1c5136fa080155d928e0d7e2b4a41ddef03e/src/app/api/prompts/route.ts)。线上实现可能独立更新；实际数量来自实时接口响应。
- 32 篇样本为有目的的跨领域阅读样本，每个方向两篇，不是随机抽样，也不能用来推断全站质量比例。两篇与 Design 专题重叠，合计 60 篇独立内容有阅读说明。
- 发布数据仅保留目录 ID、标题、类型、分类、标签及样本正文。不发布 API 响应中的作者账号、头像、媒体地址和其他无关字段；原始响应保留于已忽略的 `upstream/prompts-chat-wide/`。

官方[贡献指南](https://github.com/f/prompts.chat/blob/main/CONTRIBUTING.md)说明社区用户可以通过网站投稿并同步到仓库，并要求投稿者测试自己的提示词；没有据此确认每条内容经过平台统一评测。提示词数据采用 CC0，许可文本随项目保留。

## 四条复用路径

网页提供每一步的材料、交付物、对应原文和适配说明，还能填写任务并复制本项目编写的简版说明。各步骤只是建议的工作方式，**本次没有调用模型执行这些流程**。

1. **研究新开源项目**：需求问题 → 来源与证据表 → 仓库结构和关键路径 → 清晰的中文说明。最适合我们不断收录新项目的工作。
2. **制作研究网页**：受众与内容 → 设计和实现约定 → 浏览器实际检查 → 验收记录。先让人看懂，再补功能介绍。
3. **分析数据并形成报告**：数据口径 → 问题 → 查询或计算 → 结果核对 → 通俗解释。提示词不能补足不存在的数据。
4. **准备封面与短片**：内容重点 → 图像描述 → 实际出图 → 镜头描述 → 实际视频检查。图像和视频生成需要相应工具。

## 建议我们沉淀什么

每个保留下来的模板，记录以下信息即可：

- 解决的任务，以及不适用的情况。
- 原始链接、阅读日期、留下了哪些要求、删除了什么。
- 必填材料、可用工具和期望输出。
- 实际使用的模型、版本或日期。
- 一组真实输入输出，以及修改和失败记录。
- 与直接描述需求相比，遗漏、事实错误、人工修改量是否减少。

先从“项目研究说明、网页验收、代码审查、数据报告、清晰改写”这些反复发生的任务开始。不因模板长、标题响亮或被收录就将它变成固定要求。没有帮助的模板可以不留。
