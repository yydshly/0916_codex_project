# 实验过程与边界

2026-09-17，Windows x64，OpenPencil v0.8.4 prerelease。官方桌面和 CLI 包 SHA-256 均与上游校验文件一致。未编译主分支，未将上游完整源码或二进制纳入子项目。

## 实际过程

首次启动显示空白 Frame。初始 MCP 未启动，CLI 返回连接拒绝；通过 `Agents & MCP → MCP → Start` 启动本机服务后，`op status` 返回 running=true。没有安装全局 MCP 集成或配置模型密钥。

调用 `use-template tidemark-slate-deck` 得到七个画板，保存原版模板、导出第二页并捕获编辑器全景。新增页面，执行原创 JavaScript 批量插入脚本。

第一版把部分文字和背景容器放成同级节点，出现背景遮挡文字。已将文字改为对应容器的子节点、使用相对坐标重新生成。最终高清图已经检查，品牌、当前导航、新建按钮、搜索和状态标签均显示。

第二次 `batch_design` 修改主标题，回读 live 节点和保存文件，结果一致。最终 `.op` 两页面共 443 节点，其中模板 351、工作台 92。生成接口 nodeCount 与结果 bindings 数量有一项差异，最终计数按保存文件递归统计。

GUI 文件对话框自动化遇到 UIA 几何不可用，已取消，没有宣称 GUI 重新打开通过。改用上游 `open_document(filePath)` 与 `get --file` 重新读取文件，确认可解析且文本修改已持久化。桌面保留在生成的工作台页面。

## 验证边界

- 本实验是当前外部 Agent 编写脚本、驱动 OpenPencil，不是其内置模型接收自然语言后自主规划。
- 没有配置模型服务；未验证内置多 Agent 速度、质量和 token 成本。
- 按钮和图表是设计节点，未验证业务交互、响应式网站或后端接口。
- 未验证 Figma 导入、框架代码导出、PPTX、协作、Web 或公网部署。
- 原生编辑器小字号 UI 文字偏细，高清导出可读性较好；不同机器字体表现未比较。

已证明该库可作为外部 Agent 的真实设计执行环境：结构化插入 → 节点修改 → 文档持久化 → 原生渲染导出。配套 Skill 可提高使用便利性，本次直接调用 CLI 已完成链路。与 Claude Design 的成品质量和完整工作流尚未做同题比较。
