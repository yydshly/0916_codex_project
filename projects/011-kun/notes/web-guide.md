## 本次新增理解

### 展示能力不能只用“聊天界面”概括

核对了聊天 Markdown／公式与代码渲染、ChartSpec 契约、文件媒体预览、PPTX 预览、白板图形模型、画布动画模型与时间轴、SVG 结构工具、对话轨迹及 UI 外观包。

图表采用受约束数据契约；HTML 原型走页面渲染；白板使用结构化对象与操作；扩展面板走独立 Webview。四者不能互相推导成“模型可在任意位置运行任意前端代码”。

### 现有文档结论需要细化

1. 普通 Office 预览和专用 PPT Agent 是不同路径：源码已提供 PPT 创建、读取、编辑、复刻及导出工作流，不能一概写成只读，也不能扩大到所有 Office 格式。
2. 视频编辑器 README 的“默认随包”描述与当前打包脚本冲突。后者将 kun-video-editor 与 presentation-studio 标记为 retired，仅默认列出 social-media-sidebar；网页按非默认源码示例说明前两者。
3. 本地语音实现有英语语言限制及发布许可审查条件，不能写成普遍可用的全语言语音助手。
4. research brief 是已有编排提示入口；专题文档的专用研究状态、完整证据 schema、健康面板和质量评分仍需区分规划与现有能力。
5. 设计节点图、Graph Agent 编排、Loop 工作流都带“图／循环”的说法，但用途、状态和调度不同。

## 实现与图片说明

使用原生 HTML、CSS、JavaScript；正文直接写入 HTML，没有依赖远程请求、CDN、模型服务或前端框架。JS 仅提供目录高亮。侧栏与布局有窄屏规则，表格可在自身容器内横向查看。

页面中的四个小图是原创类型示意：富文本、代码差异、柱状图、原型交接关系。它们不是实际应用截图、真实业务数据或已执行修改。页面没有媒体播放、模型调用、任务调度等 Kun 功能的运行实现；这是研究说明网页。
