MULTIPOST EXTENSION

浏览器插件接入，
按平台要求填写与发布。

将用户准备好的文章、图文、视频和播客，按目标平台要求填写、上传，并在适配器支持时提交发布。源码覆盖 70 余个平台／服务、110 项内容适配；最终结果仍需到平台确认。

两条主线，连起来读

使用：准备 → 分发 → 核对结果。
原理：统一任务 → 浏览器执行 → 平台适配。每一步都对应具体能力与限制。

第一部分 / 使用流程

从安装到确认结果，用户怎样完成一次分发？

以“我已有内容，要发到几个平台”为例。左侧是你的操作，右侧说明这一步体现的能力。

入口已核对：研究版本点击扩展图标会打开 官网发布页；2026-09-17 的公开页面访问被转到登录页。应区分官网账号、目标平台账号，以及远程调用使用的 API Key。以下流程依据源码与官方文档整理，尚未登录或执行发布。
01

安装并打开入口

安装 Chrome / Edge 扩展，点击工具栏图标。当前版本会打开官网发布页；若出现登录页，先完成官网登录。

从这一步看能力

建立“网页编辑内容 + 扩展执行操作”的使用环境。

02

准备目标平台账号

在装有扩展的同一浏览器中，登录要分发的平台，并确认账号能进入创作后台。

从这一步看能力

执行脚本使用这些页面现有的登录会话；扩展不会替你注册账号。

实现依据 ↗
03

按内容类型准备素材

文章准备正文和封面；图文准备文案与图片；视频准备成片、简介和封面；播客准备音频与节目描述。

从这一步看能力

不同类型有不同字段。它承担分发和填表，素材制作与各平台内容审核仍是独立环节。

实现依据 ↗
04

选平台，决定是否自动提交

选择同一内容类型的目标平台。首次建议关闭“自动发布”，先观察填写效果。

从这一步看能力

同一份内容交给多个平台适配器；关闭开关通常停在填写阶段，开启也取决于适配器是否实现提交。

实现依据 ↗
05

发起分发，保留处理页面

发起发布后，等待素材处理和各平台页面打开；大视频先少选平台，观察上传是否正常。

从这一步看能力

扩展先处理资源，再打开、分组和操作标签页。它需要浏览器运行，并非将一份文件交给云端就结束。

06

逐页校对并完成提交

检查标题、正文、图片、封面、分类与标签；未自动提交的平台由你补齐必填项，再确认发布。

从这一步看能力

适配器减少重复操作，平台特有设置、登录验证、审核要求仍可能需要人工处理。

实现依据 ↗
07

确认结果，再决定是否重试

到平台内容管理页检查草稿、审核中或已发布状态。失败时先确认是否已创建内容，再重新执行。

从这一步看能力

扩展的完成提示和标签页重载，不等于取得平台发布成功凭证，也不自带防重复发布保证。

第一部分 / 使用方式

三种入口，共用浏览器执行端

差别主要在“谁准备内容、谁发起任务”。目标平台的填写与上传仍由浏览器扩展完成。

人来操作官网 / 配套编辑器自己的网页调用消息桥接 / 可信域名服务端安排任务REST API / 已绑定客户端
A

通过官网或配套编辑器手动分发

适合个人创作者，使用时无需自行写调用代码。

  1. 进入编辑入口：点击扩展图标前往官网发布页；文章可参考官方配套 Markdown 编辑器。
  2. 准备内容：输入正文，附上对应图片、视频或音频；文章检查封面和排版。
  3. 选择范围：勾选目标平台，决定仅自动填写还是尝试自动提交。
  4. 观察执行：保持浏览器打开，逐页检查上传、正文和平台必填项。
  5. 验收：以各平台内容管理页中的实际状态为准。
能带来的便利 同一份内容减少多次复制、上传和填表。
仍需要你做 内容制作、账号登录、平台差异检查与结果确认。

配套编辑器是另外的项目。官方说明要求添加题图；不能把这条编辑器要求推广为所有扩展入口的统一限制。编辑器说明 ↗ · 对应源码 ↗

B

将分发按钮接到自己的网页

适合已有编辑器、素材管理页或内容生成页面的开发者。

  1. 安装扩展：使用同一浏览器打开自己的网页和目标平台。
  2. 建立信任：网页请求加入可信域名，由用户在扩展窗口确认；已有可信域名可直接通过检查。
  3. 查询能力：通过服务状态和平台列表消息获取扩展信息与平台注册键。
  4. 构造任务：将选中的平台、内容字段与自动发布开关封装为统一数据，通过 window.postMessage 发出发布请求。
  5. 处理回执：使用请求标识关联响应；收到 received 只能说明后台接收了请求，后续继续观察发布窗口和平台页面。
能带来的便利 保留自己的内容制作界面，把平台操作交给扩展。
需要的条件 网页信任授权、已安装扩展和目标平台登录状态；该网页消息路径本身不检查云端 API Key。

C

从脚本或服务端创建远程任务

适合将发布接入内容生产流程，仍需一个在线的浏览器客户端。

  1. 取得密钥：按官方文档在控制台设置中创建 API Key。
  2. 绑定客户端：扩展联动流程弹出确认窗口，确认后在扩展本地保存密钥；扩展向服务端登记 / 报告客户端信息。
  3. 选择执行端：调用客户端列表接口，取得目标 targetClientId。
  4. 创建任务：携带 Bearer Token 调用 POST https://api.multipost.app/extension/task，指定执行端、任务类型和内容。
  5. 等待与核对：扩展 ping 收到 NEW_TASK 后打开任务 URL；调用任务详情接口追踪任务，再到平台核实最终结果。
能带来的便利 官方接口提供直接内容、已有草稿和计划任务等入口。
需要的条件 云端服务、API Key、绑定且在线的浏览器客户端；本仓库只包含扩展端，服务端调度与执行闭环未在本次验证。

第二部分 / 实现原理

本质：内容协议 + 浏览器调度 + 平台适配脚本

上层决定“发什么、发到哪里”；扩展负责“打开哪一页、怎样操作”；平台负责真正保存、审核和发布。

第二部分 / 关键机制

把“怎么实现”讲到具体动作

展开查看机制与限制的因果关系，而不是只记住几个技术名词。

为什么能不为每个平台申请一个 API Key？

多数适配函数直接操作用户已经登录的发布页面，提交动作沿用该页面的会话。网页消息桥接是否允许调用由可信域名控制；远程服务的 API Key 则用于云端鉴权。这是三层不同的条件，不能统称为“完全无需登录或密钥”。

核对实现 ↗
为什么复制正文不是简单地给输入框赋值？

标题框可设置 value 后派发 input 和 change；富文本编辑器通常维护自己的内容状态。以知乎为例，代码创建带 text/html 的粘贴事件，让编辑器按粘贴行为接收正文，再触发相关事件。页面选择器或编辑器机制变化时，这条适配路径就可能失效。

核对实现 ↗
图片、音频、视频怎样进入上传控件？

先从素材地址读取数据，再构造 File，加入 DataTransfer，把其 files 赋给页面文件输入控件并触发 change 等事件。Blob URL 是浏览器内的临时资源引用，不是已经上传到平台的永久链接。大文件与多个平台可能增加内存和等待成本。

核对实现 ↗
所有平台都只是模拟点击吗？

不是。WordPress 适配器还从页面上下文读取 nonce，调用站内媒体上传接口，再处理返回的素材地址。这说明“浏览器执行”可以结合 DOM 操作与站内请求，但每个平台的鉴权、接口和数据结构仍需分别适配。

核对实现 ↗
为什么等待页面加载后还可能填不进去？

标签页 complete 表示页面加载事件，不代表前端编辑器已准备好。适配器又使用选择器、MutationObserver、超时和固定延迟来等待具体控件。网络延迟、登录跳转和页面改版都会改变时序，因此固定等待不能保证所有场景成功。

核对实现 ↗
“完成”提示为什么不是最终发布成功？

createTabsForPlatforms 返回的是标签页。注入由页面事件触发，公共链路没有把每个注入函数的最终结果收集为发布凭证；handlePublishComplete 收到回调后直接切换完成提示。因此“已接收、已开页、已填入、已提交、已上线”需要分开判断。

核对实现 ↗
重试与任务管理做到什么程度？

标签页管理记录保存在后台内存数组；重载功能更新页面地址并再次注册脚本注入。它方便恢复页面操作，但这段实现没有提供持久队列和发布去重语义。后台重启后的任务恢复、自动重试和服务端状态一致性需要另行验证。

核对实现 ↗
网页文章抓取与发布是什么关系？

抓取脚本先按 URL 选择站点提取器；若没有取到正文，则回退到 Readability。它可给内容制作提供输入，但抓取与分发是两条独立能力。仓库中保留了调用抓取的表单组件，当前 popup / options 已转到官网，不能据此声称该旧表单就是现在的使用界面。

贯穿示例 / 同一篇文章发往知乎与火山引擎

相同输入，为什么得到不同的操作结果？

  1. 输入：标题、HTML / Markdown 正文、封面，以及两个 ARTICLE 平台标识，设置 isAutoPublish: false。
  2. 公共处理：保留原始正文，读取素材，打开两个平台的发布页面并注入不同函数。
  3. 知乎路径：使用原始标题与 HTML，派发粘贴事件写正文，通过文件控件上传处理后的封面；关闭自动发布时不触发代码中的提交点击。
  4. 火山引擎路径：填写标题和正文，等待人工检查；若把开关改为 true，该函数会直接拒绝自动发布。
  5. 得出的能力判断：它共享任务组织与素材处理，但“填写哪些字段、是否提交”由每个适配器决定；仍需在两个页面分别验收。

免登录、免密钥目标平台会话用于发布；官网入口本次访问转到登录页；远程 ping 有 API Key 检查。官网账号、平台账号与远程 API Key 是不同层次。
自动发布知乎、小红书有条件点击；火山引擎文章拒绝自动发布。按“平台 × 内容类型”评估，不能全局假设支持。

定时发布官方云端 API 有计划任务；抖音视频适配器另可填写平台定时控件。云端安排执行与平台定时上线不同；离线执行和调度可靠性未实测。
格式与稳定性适配器依赖具体页面选择器、事件及等待时间。平台改版、登录失效、素材限制都可能影响结果。

内容分发模块。

主要价值在于平台适配经验和执行端组织。适合接在编辑器、素材库或内容生成工具之后。

若要成为可靠的日常工具，还要补上结果确认、失败接管与维护机制。

01 · 复用统一内容协议

上游只整理内容、素材与目标平台，平台差异留给适配器，避免每个入口各写一遍发布逻辑。

02 · 学习具体平台的处理方式

富文本粘贴、图片上传、封面选择、页面等待与站内接口，是最有实际参考价值的实现细节。

03 · 补齐逐平台结果与重试

分别记录已填写、已提交、待审核、已发布和失败；重试前先检查是否已生成内容。
