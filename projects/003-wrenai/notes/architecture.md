# 内部技术架构：输入如何变成业务结果

研究基准与来源：[`architecture.md @ 871118e94f15`](https://github.com/Canner/WrenAI/blob/871118e94f1525c401d867074c05e7e8eefca1cc/docs/core/reference/architecture.md)、[MCP 工具接口源码](https://github.com/Canner/WrenAI/blob/871118e94f1525c401d867074c05e7e8eefca1cc/core/wren/src/wren/mcp_server.py)、本项目 [实际验证记录](engine-verification.json)。下文为原创中文逻辑拆解，不是一次完整 Agent 的执行日志。

## 一次提问前，系统已经准备好什么

| 准备物 | 处理方式 | 被谁使用 |
| --- | --- | --- |
| 模型、计算字段、关系等 YAML | context build 校验并编译为 target/mdl.json | 语义引擎；模型描述也供 Agent 获取 |
| 业务规则、术语、已确认的问题—SQL 对 | 保存在 knowledge；需要时建立可重建的检索索引 | Agent / 大模型 |
| 数据库连接配置 | 解析当前项目的 profile 和环境配置 | Wren 连接器 |
| 模型 API 与工具说明 | Agent 框架配置模型，并暴露 Wren 工具 | Agent / 大模型 |

业务规则文本与可执行模型不是同一种约束。把“收入需要扣退款”固化成计算字段，和只在提示词里写一句要求，控制强度不同。

## 完整服务端问数链路

以“2026 年 8 月各地区净收入是多少”为例。步骤是解释用的逻辑顺序，Agent 可按需求跳过、重复、补充工具调用。

| 模块 | 输入 | 内部处理 | 输出与效果 |
| --- | --- | --- | --- |
| 1. 意图理解 | 问题、会话、业务定义 | 识别净收入、订单月份、地区维度；有歧义先澄清 | 明确任务，防止答非所问 |
| 2. 上下文检索 | 任务与关键词 | 获取 MDL 模型 / 字段、规则及相似已确认 SQL；可用可选语义检索 | 相关知识片段，降低瞎猜字段和口径的风险 |
| 3. 模型生成 | 问题、上下文、工具参数结构 | 生成引用 Orders、Customers 和 revenue 的 SQL | 模型 SQL / 工具调用请求，尚无业务数字 |
| 4. Agent 调度 | 工具调用请求 | 执行 MCP / CLI / SDK 调用；Wren 加载项目 MDL 和连接配置 | 将 SQL、manifest、数据源交给查询栈 |
| 5. 语义展开与规划 | 模型 SQL + MDL + 方言 | sqlglot 解析与引用解析；wren-core 展开模型与计算字段；CTE rewrite 组织查询；规划检查和方言转换 | 实际数据源 SQL，使指标定义能被真实执行 |
| 6. 校验与修正 | SQL、规划反馈、目标数据源 | dry-plan 看展开；dry-run 检验数据源；错误返回 Agent 后获取定义 / 修正 | 执行候选或错误；合法 SQL 仍需业务验证 |
| 7. 数据执行 | 最终 SQL + 连接配置 | 数据库筛选、JOIN、聚合、排序；连接器处理返回类型 | PyArrow 表或工具序列化后的结果行 |
| 8. 结果交付 | 行数据、问题与口径 | Agent / 模型解释，应用绘制表格 / 图表；确认后可保存问答案例 | 可读答案与可复用的正确示例 |

请求由 Agent 发向工具，结果和错误从工具回到 Agent。大模型提出调用意图，Agent 程序执行调用。RAG 找的是知识，金额由计算层得出。

## 引擎如何把抽象指标落到实际字段

```text
MDL 定义：
  Orders → raw_orders
  revenue = paid_amount - refund_amount

模型 SQL：SUM(o.revenue)
等价物理表达式：SUM(o.paid_amount - o.refund_amount)
```

页面的完整展开示例是教学等价 SQL，未声称是服务端 dry-plan 的原始产物。实际规划可使用 CTE，并根据数据库方言生成不同文本。

## 三类返回路径

1. 问题不明确：Agent 追问用户，补齐日期 / 指标后再生成。
2. SQL 报错：工具给出字段、模型或数据库错误，Agent 重新获取上下文，模型修正并再次校验；重试与超时由应用控制。
3. 能运行但业务结果错误：核对原始数据、时间口径、JOIN 粒度和 MDL，由业务负责人确认后重跑；不把所有可执行 SQL 自动写成正确经验。

## 当前实验到底走了哪段

页面控件 → `makeSQL` / `makeMDL` → `WrenEngine.init` → `registerJson` → `loadMDL` → `query` → `draw` / CSV。

- 控件替代自然语言输入的理解过程，没有调用模型或 RAG。
- `registerJson` 在浏览器 / Node 注册 39 笔订单和 6 个客户。
- `loadMDL` 建立模型映射和计算字段。
- Wren WASM 通过 DataFusion 在本地执行查询；没有服务端 sqlglot、PyO3 或数据库连接器链路。
- 默认回放已验证的结果快照；只有启动真实引擎后才在浏览器重算。
- 页面导览的步骤切换只更新说明，不执行查询。

实际实验得出 2026-08 华西 19,150、华南 15,750、华东 12,350，净收入合计 47,250 元。改用实付金额口径后为 50,500 元，差额 3,250 元。数字来自合成数据的实际 WASM 计算，不是模型编造或生产数据。

## 达到业务效果需要哪些层一起正确

问题范围明确 → 上下文包含相关口径 → 模型正确生成操作 → Agent 正确调用 → MDL 准确映射业务 → 数据本身正确且查询粒度正确 → 展示保留范围与单位。

端到端验收必须覆盖上述整条链路。当前 36 组实验支持对引擎计算与展示的判断，不支持对完整自然语言准确率的判断。
