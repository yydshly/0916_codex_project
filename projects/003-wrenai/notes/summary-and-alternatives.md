# WrenAI：下次从这里恢复理解

研究整理：2026-09-16。Wren 源码基准与运行版本见子项目 README；其他产品仅核对官方文档，没有做横向性能或准确率实测。

## 30 秒摘要

**WrenAI 是面向 Agent 的业务问数基础设施：模型理解自然语言需求，MDL 统一业务口径，Wren 展开定义并规划查询，数据库计算真实数字，上层应用解释与展示。**

- **能力**：围绕结构化数据做筛选、关联、聚合、排名和趋势查询，供销售、运营、库存等分析使用。问数体验由模型、Agent、Wren、数据库和应用共同构成。
- **原理**：资料准备 → 按需检索 → 模型生成查询 → Agent 调用工具 → 语义展开与校验 → 查询计算 → 解释结果；错误和歧义返回前序处理。
- **价值**：降低查数门槛，统一并复用业务定义，减少重复查询开发，保留 SQL 和结果作为核对依据。
- **本质**：把语言意图接到可执行的业务能力。Wren 的特色是语义层；并非所有业务都需要 RAG、语义层或复杂 Agent。
- **适合**：结构化数据、口径明确、反复出现、可用标准答案核对的分析问题。
- **边界**：模型理解和结果解释仍可能出错；扫描件解析、预测、因果判断和交易执行需要额外能力。

![WrenAI 原理与场景引导图](../app/media/wrenai-summary.png)

阅读顺序：先看本质与能力 → 对照使用场景 → 看内部处理链路 → 根据需求选择实现路线 → 用实验核对计算。

## 输入、准备、处理、输出

| 环节 | 内容 |
| --- | --- |
| 用户输入 | 问题、日期、筛选范围、分组或排序需求 |
| 事前准备 | 数据连接与质量、MDL 表字段映射与指标定义、业务术语和正确案例、模型与 Agent 工具、权限、验收样题 |
| RAG（按需） | 找到相关模型说明、规则、术语或 SQL 案例，提供给模型；不生成经营数字 |
| 模型与 Agent | 理解需求、提出查询或工具调用、执行工具并利用反馈修正；信息不够时澄清 |
| Wren | 将面向业务模型的查询展开为具体计算与关联，规划目标 SQL；不是大模型本身 |
| 计算层 | 服务端数据库经连接器执行；本研究 WASM 实验在本地内存计算 |
| 输出 | SQL、真实结果表、应用图表及解释，或澄清问题与错误 |

本研究采用预设问题和 SQL，没有接入完整大模型问数循环。当前主线的 `wren ask` 仅组装提示词，不能把它的输出误认为已经调用模型并执行查询。

## 两类规则必须区分

1. **帮助理解的资料**：字段说明、业务术语、文字要求、示例，帮助模型选择正确操作。
2. **必须执行的定义和约束**：计算公式、参数校验、访问范围、数据库权限，由对应程序执行。MDL 不能替代所有权限机制。

“净销售额扣除退款”写在提示词中，依赖模型生成正确表达式；写进指标公式或业务接口中，程序按公式计算。模型仍可能选错指标或月份，数据和定义也可能有误，因此 SQL 合法不等于业务答案正确。

## 还有哪些实现方案

| 路线 | 模型承担的工作 | 程序承担的工作 | 适用判断 |
| --- | --- | --- | --- |
| 固定报表 / BI | 可以不用模型 | 固定查询与可视化 | 重复、固定统计需求 |
| 模型 + 固定接口 | 选接口、填参数 | 参数验证、权限、固定计算 | 少量明确问题，容易控制范围 |
| 直接 Text-to-SQL | 根据问题与表结构编写 SQL | 校验和执行 | 简单库试验、分析师辅助 |
| RAG + Text-to-SQL | 使用检索到的知识编写 SQL | 检索、校验和执行 | 表多或业务知识多，仍需验证口径 |
| 模型 + 语义层 | 选择指标、组织查询 | 展开可复用指标和关联 | 多人、多应用共享口径；Wren 路线 |
| 多步骤 Agent | 拆解、选工具、利用反馈继续分析 | 执行每次工具请求 | 探索与复杂追问；可组合前述路线 |

共同模式是“理解需求 → 补充知识 → 可执行请求 → 查询计算 → 解释结果”。差异影响可靠性、灵活性和维护成本，不只是界面或实现细节。RAG 主要补充上下文；语义层统一业务定义；Agent 编排步骤，各自解决不同问题。

固定接口例子：用户问“2026 年 8 月华东净销售额” → 模型提取月份和地区 → 调用 `sales_summary(month, region)` → 后端按固定口径查询 → 返回数字与统计范围 → 展示。此路线可以不让模型编写 SQL，也不需要 RAG。

## 产品与库对照

| 对象 | 官方能力与定位 | 选型说明 |
| --- | --- | --- |
| [Cube / Cube Core](https://docs.cube.dev/docs/introduction) | 语义层统一指标、关联、访问规则和查询接口 | 接近语义层路线；区分开源 Core 与完整产品功能 |
| [SQLBot](https://github.com/dataease/SQLBot) | 大模型、RAG、Text-to-SQL、术语及 SQL 示例、问数图表和嵌入 | 可用于体验完整问数产品，再核对自己的数据与指标 |
| [Snowflake Cortex](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst) | 语义视图描述指标和关系，支持自然语言查询 | 面向 Snowflake；文档目前建议从 Analyst 转向 Agents |
| [Databricks Genie](https://docs.databricks.com/aws/en/genie) | 数据团队配置可信数据、指标、规则与查询示例 | 适合已有 Databricks 平台的团队 |
| [LangChain / LangGraph SQL Agent](https://docs.langchain.com/oss/python/langchain/sql-agent) | 获取表结构、生成、检查、执行、修正查询及结果回答 | 开发框架；不自动具备企业业务模型和完整权限 |
| [Vanna](https://github.com/vanna-ai/vanna) | SQL 工具、检索和用户上下文构成的问数 Agent | 仓库已于 2026-03-29 归档，适合研究时参考；新选型需考虑维护 |

上述能力描述来自官方资料；不据此宣称产品能保证业务正确率。建议固定需求先用业务接口，需要跨问题复用口径时考虑语义层，确有连续探索需求时再增加 Agent。

## 实测证据与不确定性

已验证：`@wrenai/wren-core-wasm@0.4.1` 在 39 笔合成订单、6 个虚构客户上运行 36 组查询，与独立逐笔计算一致；覆盖计算字段、显式 JOIN、筛选、聚合、排序和未知字段拒绝。8 月净收入 47,250 元，实付金额 50,500 元。

未验证：完整自然语言准确率、RAG 命中率、模型自动修正、真实数据库连接、生产规模和多用户权限。36 组查询只能说明本组引擎实验通过，不能解释为问数准确率 100%。
