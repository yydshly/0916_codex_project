BUSINESS INTELLIGENCE / RESEARCH SYNTHESIS

WrenAI：让业务定义驱动 AI 问数

能力：销售、运营、库存等结构化问数　｜　价值：降低查数门槛，统一口径，核对依据
003
本质：自然语言需求 → 业务知识 → 可执行请求 → 查询计算 → 解释结果

Wren 的特色是语义层：MDL 定义业务怎么算，模型与 Agent 组织查询，程序执行。RAG 按需补充上下文。

01事先准备：让业务知识和数据各就各位

业务数据

订单、客户、退款等结构化表
核对主键、单位、日期与质量

MDL 业务模型

表映射、关联、指标公式
编译成引擎可执行的定义

规则与正确案例

术语、口径、已确认 SQL
可选检索索引 → 提供模型上下文

工具与连接

模型服务、Agent、数据库连接
工具参数、访问权限与执行策略

02内部处理：完整服务端问数链路 / 按需检索、校验与重试，并非固定流水线

01理解问题明确指标、时间
范围与分组维度
02检索上下文RAG 找模型
规则与相似案例
03模型生成结合规则生成 SQL
提出工具调用请求
04Agent 调用执行工具请求
MCP / CLI / SDK
05Wren 规划展开 MDL、转换校验
sqlglot / CTE / Rust
06数据库计算筛选、关联、汇总
返回真实结果行
07解释与展示模型解释数字
前端表格与图表
08确认与积累确认后保存问答
与对应正确 SQL
↶ 信息不足：理解阶段 → 向用户澄清↶ 校验报错：错误反馈 → 模型修正 → 再校验↶ 经验复用：确认后的案例 → 后续检索
RAG 找知识；模型应用规则；MDL 固定计算；数据库产生数字。

文字要求依赖模型遵循；结构化定义、校验和权限由程序执行。检索到规则，不代表规则已经正确应用。

INPUT / 输入

问题 + 数据 + 业务定义

自然语言问题、结构化数据、MDL、
业务规则与可选历史案例。
RAG 不负责生成经营数字。

EXAMPLE / 合成数据实验

“2026 年 8 月各地区净收入？”

实付 − 退款，排除取消与内部订单。
本实验按订单日期归属统计月份。

净收入 47,250 元实付 50,500 元
OUTPUT / 输出

SQL + 数据 + 可读答案

查询结果、分析解释、图表 / 看板；
必要时返回澄清问题或错误信息。
数值计算与模型解释分别核对。

03 / SCENARIOS

适用场景

  • 优先试点：销售经营、常规运营报表
  • 辅助使用：库存分析、分析师探索
  • 前提：数据结构化、口径清楚、可核对
  • 预测、自动付款和审批需要额外系统
04 / VALUE

业务价值

  • 自然语言连接业务工具，降低查数门槛
  • 复用指标定义，减少口径漂移
  • 保留 SQL 与结果依据，便于追溯
  • 积累正确案例，减少重复分析工作
05 / RELIABILITY

可执行 ≠ 业务正确

  • 逐层检查数据、检索、生成、计算和解释
  • 订单月与退款月不同，合法 SQL 也会答错
  • 试点：固定指标 + 只读查询 + 标准答案
  • 重要结果复核；单期数字不能证明原因

06方案选择：同一种思路，规则落在不同地方

固定指标 → 业务接口

模型选接口、填参数
后端执行固定公式；可不需要 RAG

灵活问数 → Wren 语义层

指标和关联统一定义、多次复用
模型组织查询，引擎展开执行

自由 SQL → 辅助分析

表结构 + 按需检索 + 模型写查询
业务口径与 SQL 都需核对

多步探索 → 增加 Agent

拆解、反复查数、比较和解释
可调用业务接口，也可调用 Wren

记忆点：提示词里的“扣退款”依赖模型遵循；指标公式里的“扣退款”由程序计算。定义正确后，还要选对指标、日期和范围。

已验证：36 组 Wren WASM 查询与独立计算一致

合成数据；MDL、显式关联、筛选、聚合、排序和未知字段报错。

未验证：大模型问数、RAG 与生产数据库

不能据此声称端到端准确率。实际业务需要标准问题集验收。
